# Analytics

Analytics provide insight into the usage trends, search quality, and end-user engagement of your customers app. The console provides an interactive dashboard experience powered by Looker.

> [!NOTE]
> **Note: Metrics are refreshed about every 6 hours, so it can take several hours before anyone can use the Analytics page after an app is created.**

## **User events for analytics**

Gemini Enterprise uses user events to generate search-related metrics, such as search count and click-through-rate. No additional configurations are needed if your customer is using the user interface to search and get answers through the Gemini Enterprise assistant. However, if they use the Gemini Enterprise APIs in their apps, they must configure the search in the app to capture the user events and then import user events to the app.

Gemini Enterprise apps require the following user events to get the metrics:

- **Search events:**
  - Required for click-through-rate.
- **View-item events:**
  - Required for click-through-rate.
- **Impressions:**
  - Impressions, such as item views or clicks, are attributable to Google when ingesting user events.
- **Attribution tokens:**
  - Attribution tokens are unique IDs generated by Google and returned with each search request.
- **Search logs:**
  - Search logs are based on search requests.

## **View Gemini Enterprise analytics**

Your customer can view search analytics for their app. They can view the metrics related to the search calls made to their app. If their app is connected to multiple data stores, then making search calls to the app by specifying the engine resource is recommended so that they can get results from across all its connected data stores.

There are four main metric categories through which to view analytics data, these are:

- **Adoption:**
  - Adoption metrics show how people are using the product over time, they are metrics on the status of user adoption.
- **Usage and Quality:**
  - Usage and Quality metrics show user feedback and app usage over time.
- **Agent:**
  - Agent metrics are related to in-app agents, such as deep research, idea generation, and custom agents.
- **Value:**
  - Value metrics show the cost savings achieved by users querying data with the app.

There are further filters for each tab which can be used to explore the data, these include:

- **Date Range**: to pick a start and end date to view data for a specific range.
- **Activity interval**: to change the view on the Active Users chart to observe daily, weekly, or monthly data.
- **Rate Interval**: to change the view for the "Rate" charts (Churn Rate and Retention Rate).
- **Product Type Filter**: to focus on one product type (like Search, Answer, Assistant, or Other) or view the Total for all of them combined.

## **Metrics definitions**

The following table describes how metrics are defined.

| Metric group | Metric name | Metric definition | Notes |
| --- | --- | --- | --- |
| **Adoption** | **Daily active users** | Count of active users per day | A user is considered active if they sign in and trigger any API calls, such as when landing on the home page. |
| **Adoption** | **Weekly active users** | Count of active users per week. The week starts on Monday and ends on Sunday. |
| **Adoption** | **Monthly active users** | Count of active users per month |
| **Adoption** | **7d retention rate** | Count of returned user in the current 7-day period / count of active user in the previous 7-day period | A user is considered as a returned user if the user is active during the current 7-day period and the previous 7-day period. |
| **Adoption** | **7d growth rate** | The percentage difference between the number of active users in the current seven-day period and the previous seven-day period |
| **Adoption** | **7d churn rate** | Count of churned users in the current 7-day period / count of active user in the previous 7-day period | A user is considered churned if the user was active in the previous 7-day period, but is not active in the current 7-day period. |
| **Adoption** | **28d retention rate** | Count of returned user in the current 28-day period / count of active user in the previous 28-day period |
| **Adoption** | **28d growth rate** | The percentage difference between the number of active users in the current 28-day period and the previous 28-day period |
| **Adoption** | **28d churn rate** | Count of churned users in the current 28-day period / count of active users in the previous 28-day period |
| **Adoption** | **Seats purchased** | The number of licenses (seats) the organization has purchased | Includes all seats purchased since registering with Gemini Enterprise. |
| **Adoption** | **Seats claimed** | The number of user licenses that have been assigned to and accepted by individuals within your organization | Includes all seats claimed since registering with Gemini Enterprise. |
| **Usage and quality** | **Search count** | Total number of search |
| **Usage and quality** | **Answer count** | Total number of query where Gemini Enterprise has generated an answer | Answers generated by an agent are not included in this count. |
| **Usage and quality** | **Action count** | Total number of query answered by Gemini Enterprise | Includes actions such as creating an email template. |
| **Usage and quality** | **Click-through rate (CTR) per search** | Total number of search clicks / search count | Search clicks include clicks on search results and internal references. |
| **Usage and quality** | **Page view per category** | Total number of view for each category page |
| **Usage and quality** | **Feedback like and dislike count** | Count of likes and dislikes sent by users | A record of the thumbs-up/thumbs-down feedback responses sent by the app's users. |
| **Usage and quality** | **Feedback dislike reasons breakdown** | Percentage of the dislike reasons | When a user dislikes a generated answer, they can select multiple reasons to explain their dislike. The percentage shows how often each reason was selected. |
| **Usage and quality** | **Successful search rate** | Successful search count / search count |
| **Usage and quality** | **Successful answer rate** | Successful answer count / answer count |
| **Agents** | **Monthly active agent users** | Total number of active users who used the agent in the last calendar month. |
| **Agents** | **Monthly agent chat sessions** | Total number of chat sessions initiated by the users interacting with a specific agent during the last calendar month. | A chat session is defined as a user interacting with an agent within the same chat thread on a single day. If the user continues the conversation in the same chat thread on a subsequent day, it will be considered a new session. |
| **Agents** | **Monthly agents used** | Total number of agents that had at least one active user during the last calendar month. |
| **Agents** | **Monthly total chat sessions** | Total number of chat sessions initiated by the users interacting with the agents during the last calendar month. | A chat session is defined as a user interacting with an agent within the same chat thread on a single day. If the user continues the conversation in the same chat thread on a subsequent day, it will be considered a new session. |
| **Agents** | **Monthly agents created** | Total number of Agents that were created in the last calendar month. |
| **Value (public preview)** | **Successful search** | Count of successful searches. | The number of successful searches are determined by the user behavior after a search. A search is considered successful if one of the following occurs: <br> - If a search result is clicked before a new search is initiated. <br> - If the response from a search includes a people search result, and isn't followed by another search within two minutes. This is because people-search results are displayed on the search result page and don't typically require a click. |
| **Value (public preview)** | **Successful answer** | Count of successful answers | An answer's success is determined by user behavior after it is generated. Success is measured by feedback provided or how soon a follow up question was asked. <br> - If the user thumbs-up the answer, the query is considered successful. <br> - If there is no feedback and the user does not ask another query within 30 seconds, the query is assumed to be successful. |
| **Value (public preview)** | **Employee hours saved for selected dates** | (Successful search count + Successful answer count) x Minutes saved per successful answer |
| **Value (public preview)** | **Value saved for selected dates** | Hours saved within the dates selected ✕ Average employee hourly rate | To view this metric, in the Value tab, specify an hourly rate for the Employee Hourly Rate field. |
| **Value (public preview)** | **Projected annual employee hours saved** | (Successful search count + Successful answer count) x Minutes saved per successful search | The projected annual successful search count is derived from the successful search count within the chosen date range. Each query is estimated to save three minutes, an estimate based on Google's internal research. |
| **Value (public preview)** | **Projected annual value saved** | Projected annual employee hours saved ✕ Average employee hourly rate | To view this metric, in the Value tab, specify an hourly rate for the Employee Hourly Rate field. |
